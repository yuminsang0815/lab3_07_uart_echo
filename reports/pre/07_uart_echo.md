# 실험 전 레포트: PC-FPGA UART 에코 통신

작성일 2026-09-25.

## 1. 동작 원리와 핵심 파라미터 계산

### 동작 원리
온보드 50 MHz 메인 클록을 분주하여 비동기 직렬 통신 표준인 UART(Universal Asynchronous Receiver/Transmitter) 통신을 구현한다. 통신 설정은 9600 보오율(Baud rate), 8 데이터 비트, 패리티 없음(No parity), 1 정지 비트(8N1) 프로토콜을 사용한다.
수신부(`uart_rx`)는 비동기 입력 신호인 `uart_rxd`를 2단 동기화기(`ASYNC_REG`)로 샘플링하여 메타스테이블을 방지한다. 평상시 High(1) 상태를 유지하다가 Low(0)로 떨어지는 Start 비트의 하강 에지를 감지하면 반주기(DIV/2) 뒤에 중앙값을 재확인하여 노이즈 글리치를 필터링한다. 이후 1비트 주기(DIV)마다 각 데이터 비트의 정중앙을 샘플링하여 8비트 데이터(LSB-first)를 복원하고, 마지막 Stop 비트가 1인지 확인하여 프레이밍 에러(Framing error) 여부를 판정한다.
송신부(`uart_tx`)는 수신 완료 신호(`rx_valid`)가 발생하면 `last_data`에 저장하여 온보드 8개 LED에 이진수로 표시함과 동시에, 송신 모듈이 대기 상태(`tx_ready=1`)일 때 `tx_valid` 펄스를 인가하여 수신된 바이트를 PC 터미널로 즉시 되돌려 보내는 에코(Loopback Echo) 동작을 수행한다.

### 핵심 파라미터 계산
1. **보드 환경 보오율 분주 카운트 (`DIV`)**:
   - 시스템 주 클록 주파수 $f_{\mathrm{clk}} = 50\text{ MHz} = 50,000,000\text{ Hz}$
   - 목표 보오율 $\text{BAUD} = 9,600\text{ bps}$
   - 1비트 전송에 필요한 클록 주기 수 (반올림 포함 정수 분주비):
     $$\text{DIV} = \frac{f_{\mathrm{clk}} + \frac{\text{BAUD}}{2}}{\text{BAUD}} = \frac{50,000,000 + 4,800}{9,600} = \left\lfloor\frac{50,004,800}{9,600}\right\rfloor = 5,208\text{ cycles}$$
   - 실제 생성 보오율:
     $$\text{BAUD}_{\mathrm{actual}} = \frac{50,000,000}{5,208} \approx 9,600.61\text{ bps}$$
(오차율 약 $+0.006\%$로 UART 허용 오차 $\pm 2\%$ 이내 완벽 충족)
   - Start 비트 중앙 확인 타이밍: $\frac{\text{DIV}}{2} - 1 = 2,604 - 1 = 2,603\text{ cycles}$

2. **시뮬레이션 가속 축소 파라미터**:
   - 9600 bps 기준 1비트 전송 시간은 약 $104.16\text{ \mu s}$로 길어 시뮬레이션 시간이 과다 소요되므로, `CLK_HZ = 800`, `BAUD = 100`으로 축소 인가한다.
   - 축소된 분주 카운트:
     $$\text{DIV}_{\mathrm{sim}} = \frac{800 + 50}{100} = 8\text{ cycles}$$
   - 시뮬레이션 환경에서는 8클록마다 1비트가 직렬 전송되어 검증을 고속으로 수행한다.

## 3. 테스트벤치 자극과 기대 결과

시뮬레이션 환경에서는 축소 파라미터(`DIV=8`) 조건에서 `fork-join` 병렬 블록을 사용하여 데이터 송신과 에코 수신 검증을 동시에 진행한다.

| 검사 순서 | 송신 데이터 문자 / 16진수 | 기대 수신 에코값 (`observed`) | 기대 LED 표시 (`led`) | 판정 기준 및 검증 의미 |
|:---:|---|:---:|:---:|---|
| Check 1 | 문자 'A' / `8'h41` (`0100_0001`) | `8'h41` | `8'h41` | 첫 번째 바이트 직렬 에코 및 LED 래치 검증 |
| Check 2 | 문자 'Z' / `8'h5A` (`0101_1010`) | `8'h5A` | `8'h5A` | 비트 반전 패턴에 대한 수신/송신 안정성 검증 |
| Check 3 | 줄바꿈 '\n' / `8'h0A` (`0000_1010`) | `8'h0A` | `8'h0A` | 제어 문자 전송 및 연속 프레임 처리 검증 |

- 추가 검증: 시뮬레이션 종료 전 `dut.rx_framing_error` 플래그가 0인지 검사하여 정상적인 Stop 비트 수신을 보장한다.

## 4. 시뮬레이션 결과 및 수정 실험

### 정상 시뮬레이션 확인
- **[종료 로그](../../evidence/07/vscode/simulation.txt)**: `LAB3_UART_ECHO_PASS checks=3`, 종료 시각 `9910000 ps (9910 ns)`
- **[파형 분석](../../evidence/07/vscode/wave.png)**:
  - `uart_rxd`로 0x41이 인가될 때 Start(0)가 감지된 후 정확히 반주기 뒤에 노이즈 유무를 판단하고, 8클록 주기로 데이터 비트가 샘플링되어 `rx_data`에 래치됨을 확인한다.
  - `rx_valid`가 1클록 펄스로 뜨는 순간 `tx_valid`가 활성화되고, `uart_txd` 신호가 Low(Start)로 떨어지며 동일한 0x41 직렬 비트열을 출력함을 확인한다.
  - 3개 바이트가 순차 처리된 후 `framing_error` 발생 없이 `checks=3`을 달성하고 정상 종료된다.

### 수정 실험 (오류 주입 및 복구)
`BAUD` 파라미터(또는 `DIV`)를 송수신 한쪽만 고의로 불일치시키거나 비트 시간을 수정하여 비동기 샘플링 오류 검출 신뢰성을 점검한다.

| 실험 단계 | 설정 내용 | 기대 동작 | 실제 실행 결과 | 비고 |
|---|---|---|---|---|
| 정상 실행 | `DIV = 8` (송수신 일치) | 3바이트 정상 에코 | `LAB3_UART_ECHO_PASS checks=3` (9910 ns 종료) | 정상 통과 |
| 고장 주입 | 테스트벤치의 `DIV`를 8에서 10으로 변경 | 비트 주기 불일치로 인한 샘플링 위치 이탈 | `echo != expected` 또는 `framing_error` 감지, `$fatal` 강제 중단 | 통신 타이밍 검증 신뢰성 확인 |
| 원복 복구 | `DIV = 8` 복원 | 정상 샘플링 복원 | `LAB3_UART_ECHO_PASS checks=3` 복구 | 정상 확인 |

## 5. 보드 실험 계획 및 관찰 항목

### 하드웨어 환경 및 핀 매핑
- **타깃 FPGA**: Spartan-7 `xc7s75fgga484-1`
- **클록 및 리셋**: 온보드 50 MHz 클록 (B6 핀), 리셋 푸시버튼 K4
- **UART 통신 핀**: `uart_rxd` (C6, 보드 기준 수신), `uart_txd` (F6, 보드 기준 송신) - USB-to-UART 브릿지 연결
- **출력 표시**: `led[7:0]` (N5, M1, M3, M7, N7, M2, M4, L4)

### 보드 관찰 절차
1. PC와 FPGA 보드를 USB 케이블로 연결하고 장치 관리자에서 할당된 가상 COM 포트 번호를 확인한다.
2. PC 터미널 프로그램(Tera Term, PuTTY 등)을 실행하여 해당 포트를 `9600 Baud, 8 Data bits, None Parity, 1 Stop bit, Flow Control None`으로 설정하고 `Local Echo` 옵션을 반드시 꺼둔다(Off).
3. Vivado Hardware Manager로 비트스트림(`lab3_uart_echo.bit`)을 다운로드한 후 K4 리셋을 인가하여 LED가 모두 소등(`0x00`)되는지 확인한다.
4. PC 키보드로 문자 'A'(`0x41`)를 타이핑했을 때, 로컬 에코가 꺼진 상태에서도 터미널 화면에 'A'가 반환 출력되는지 확인하고, 보드의 `led[7:0]`에 `0100_0001`이 이진수로 점등되는지 관찰한다.
5. 여러 영문자, 숫자 및 특수문자를 연속 입력하며 화면에 입력한 문자가 누락 없이 반환되는지 확인하고 사진 및 영상으로 기록한다.
